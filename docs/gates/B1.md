## G-B1.1 — CAPTURE gate (`python3 python/gates/b1_gates.py CAPTURE`)

Two independent collector runs (`python/collect/binance_daily.py`, pyarrow
via `uv run`): 3,362 daily BTCUSDT bars, **2017-08-17 → 2026-10-30**,
`rows == calendar_days` (the 1d grid is fully tiled — crypto trades 7d/week,
zero interior holes), integrity contract PASS (monotonic, no future rows,
OHLC sane low≤open/close≤high, volumes ≥ 0).

```
B1-GATE-CAPTURE {"run1": {"rows": 3362, "first_day": "2017-08-17", "last_day": "2026-10-30", "tiled": true, "sha256": "01c6c3296136cc38", "integrity": "PASS"}, "run2": {"rows": 3362, "sha256": "35edba5e00295b62", "integrity": "PASS"}, "determinism": {"rows_a": 3362, "rows_b": 3362, "history_identical": true, "last_row_live_fields": ["close_qvol", "n_trades", "volume"]}, "registry": {"readback": "rows |                              sha256                              | verified  ------+------------------------------------------------------------------+--", "sha_matches": true, "no_open_gaps": true, "training_ready": true}, "training_lock": {"unjustified_blocked": true, "justified_unlocks": true}, "wall_seconds": 29.5, "ok": true}
SUMMARY {"CAPTURE": true}
```

MEASURED:

* **Determinism pin:** two consecutive captures are
  `history_identical: true` (all rows except the live day). The differing
  final row is today's in-progress bar (close/volume/trades still updating
  with the live market) — the honest PIT boundary, not a capture defect.
  Day-close byte-identity across UTC rollovers is a **planned pin** in the
  next capture gate (measured so far only on same-live-day runs).
* **Registry:** `d3.datasets` row `binance/BTCUSDT/1d` —
  rows=3362, sha256 matches the D0 artifact byte-digest, `verified=t`,
  `d0_path=data/d0/binance/BTCUSDT/1d.parquet` (repo-relative; artifacts
  stay out of git by `.gitignore`, only manifest paths live in D3).
* **Gap calendar (§14 honest-ledger semantics):** the dataset ships with
  2 REAL, justified gaps — `2010-01-01→2017-08-16 exchange-closed,
  justified`(pre-listing; deeper BTC history routed to the Kraken/ItBit
  TODO row) and `2026-10-30 late, justified` (in-progress live day).
  `d3.v_open_gaps` for the dataset: **0 rows**.
* **Training-lock negative test (the B-GATE "no training before" pin):**
  a synthetic dataset with an open, unjustified gap is EXCLUDED from
  `d3.v_training_ready` even when `verified` is manually flipped TRUE;
  granting an explicit justification unlocks it. The lock is enforced by
  the view, not by convention.
